AGENTS · Agent 生产总纲

0 · 秩序

白皮书 > IF-BluePrint(含台账) > SOP-P1 > 代码。冲突时上位胜出,永不去改。

1 · 会话启动

  1. 读 progress.json(JSON 本体)——对齐当前 PR 与状态;
  2. 读 PROJECT_MAP.html——定位目标文件;⛔ 禁止全库 grep 寻路;
  3. 执行其 current_pr 指向的 SOP-P1 第 2 章 PR 卡——卡上六要素即全部指令,无需他问。

2 · 三色判定

  • 🟢 自决:PR 白名单内写码 / 写测试 / 修编译错 / 跑 cargo test / 按 PROJECT_MAP §4 维护地图
  • 🟡 保守:规格歧义 → 取最保守实现,commit 注明 [CONSERVATIVE]
  • 🔴 HALT:改 L0 契约 / 白皮书 / 门禁 / SOP-P1、越白名单、测试连红 3 次不克、§18 任何事项

3 · 五条红线

  1. 永不修改宪法层:白皮书 / IF-BluePrint / SOP-P1 / G 门禁 / 本文件 / PROJECT_MAP 的规则节
  2. 测试断言只许加固,永不放松——改松换绿 = 造假
  3. diff 越出 PR 卡触碰白名单 = 违规(常伴白名单除外,见 §5)
  4. HALT 时:progress.json 置 blocked_by_hitl=true + halt_reason,停手,不猜
  5. 完成两阶段:CI 全绿 + status=AWAITING_REVIEW = 机器发言;人类审 diff 并合并 = 最终发言,AI 永不宣称"PR 已完成"

4 · 状态与历史

progress.json = 唯一运行态,随 PR 完成与代码同 commit(git log 即审计轨迹); 台账 = 宪法记录,只收 HALT 裁决与阶段退出;PROJECT_MAP §3 日志 = 结构史,只收文件生/改/删。三史分立,永不互写。

5 · 地图(常伴白名单)

  1. 常伴白名单:progress.json 与 PROJECT_MAP.html 对所有 PR 永久可触碰,不计越界;
  2. 新增 src 文件 / 跨模块公共签名变更 → 同 PR 内更新地图条目 + 追加其 §3 日志行 + 刷新生命周期标注;
  3. 地图与实际 *.rs 文件不一致 = CI 红(map_check.py,G12 实例化);
  4. ⛔ 地图内禁止出现方法签名与实现细节。
  5. PR 交付的命令清单必须含 `python3 tests/tools/map_check.py`—— AI 无终端,靠本条保证不漏提示;CI 生效前,本机运行即裁判
