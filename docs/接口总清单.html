第1章 · 总则

1.1 四条推导律（接口设计的宪法依据）

#推导律出处对接口设计的强制约束
①参数透传同构铁律：测试驱动与网络 IPC 完全同构，接入真实 Socket 时核心渲染逻辑变更率 0.00%§2Phase 1/2 的 scaffold 不得另造测试接口，只能"直注"最终 IPC 的同构强类型；接口形状以 Phase 3/4 终态为准倒推
②模块拓扑锁死§15.2契约类型归 interpop-core；渲染切面归 interpop-render；原子切面归 interpop-atoms；scaffold 仅许依赖 core，反向严禁
③白名单收敛§11.1 / §14.2 / §0线程任务接口 = 封闭枚举（3 项）；下行事件 = 封闭枚举（7 项）；接口枚举本身即宪法，加变体须走 §18 门槛
④有意预留不补齐§18.1不为复合组件设内核接口；不为 golden hash 预写实测值；wgpu/zbus/accesskit 以 Feature 门控位预留

1.2 三条分界律（生产 / 调试平衡的裁决规则）

#分界律内容
①出线即生产凡出现在 NDJSON wire 上的接口都是生产契约，受 §14.2 冻结——恒为 5 动词 + 7 事件。调试信息一律不出线；确需客户端可见，只能折叠进既有 warning/error 的 reason 枚举，新增枚举变体 = 协议变更 → §18 门槛。平衡由通道拓扑保证，不靠自觉。
②观测三档进程内（tracing / debug_assertions，完全自由）→ 取证文件（runtime-dir 下的 *.log，带 schema_version 自由演进，不触发冻结）→ 出线（7 事件，§18 门槛）。默认最低档。
③三种合法归宿出线（生产契约）/ 诊断档（进程内或文件）/ 测试档（#[cfg(test)] / dev-dependency / feature="debug-tools"）。没有第四种。任何"后台写日志线程"冲动属 §11.1 白名单扩充 → 须附 Criterion 数据走 §18。

1.3 两条工程律（随首个实现 commit 同轨落盘）

#工程律内容
①MSRV 地板workspace 声明 rust-version = "1.86"、edition = "2024"，注释标注 Debian 13 (trixie) rustc 基准（1.86 系 = edition 2024 首发编译器）。CI 双端矩阵见第9章。
②内部 semver 纪律0.x 阶段 minor 版本变更 = breaking；跨 crate 调用必须显式升版本号。效果：凡需下游同步升级的变更在 Cargo 依赖解析层强制可见，静默连锁从"可能"变为"不可能"。

1.4 第三方类型切面纪律（可验证性质）

第三方类型不出切面，跨切面契约零第三方类型。
· L0 契约与 NDJSON wire：100% 自有类型——taffy/wayland/zbus 版本变更物理上不可能触达外部客户端；
